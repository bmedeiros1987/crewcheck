# Schema-v2 protocol and CLI integration — OFF

Base: reviewed remote ba2654e970af4c7ed43becef30644bc83dd757d1. This local delta does not configure an executor, connection, new route, permission, credential or live publisher. Default executable CLI and workflow publication guards remain OFF. No production schema migration occurs.

The existing createJournalProtocol dispatches schema-v2 frames pinned to plan/generation/revision, with approval supplied outside frames. Python PlannedJournalTransport mirrors record schema, immutable identity and response revisions, rejects caller outcome flags, and blocks permanently after an uncertain reply. The existing platform composition accepts explicit journal capabilities, not environment credentials. Direct journal rollover remains available under prior reviewed approval/proof gates; serialized rollover/rebinding is deliberately not exposed here, so it cannot silently change executor identity.

mobile_internal.main(argv, planned=...) uses the real existing allocate/validate/publish parser/flags and guard. The optional programmatic controller requires the existing injected transport and explicit store capabilities; executable invocations cannot obtain it through flags/env/import paths. Allocation durably reserves/starts before one injected edit creation, saves the original ID, verifies inventory and writes only phone policy. Existing validate runs its manifest/signature/provenance checks, then independent Node artifact verification decides finalization. Existing evidence stays playSubmissionAllowed=false; metadata cannot enable submission. The controller checks actual bytes/manifests again before staging and pins source/controller/run.

New stage_started durably precedes an injected upload/staging callback. Lost staging response leaves this state locked; normal retries/resume are refused. commit pending and SQL readback precede the single commit callback. Mobile/internal only, shared package reservation unchanged. No Wear/joint commit path is added.

Official edit reader models use injected request only: original edits.get, edits.tracks.list, edits.bundles.list and edits.apks.list, strict HTTP/schema/list/code/expiry/identity checks, original edit reread, bundled/APK version floor, bundle byte hashes, retained target and full non-target snapshot digests. No global fetch/client is used. Unknown or bounded pagination metadata blocks. Review and other-edit authority remain unknown; a separate trusted review/edit-coordination proof verifier is required, never a frame flag. Inactive commit adapter uses changesNotSentForReview=true plus ERROR_IF_IN_REVIEW, checks original staged state again after pending, and never retries or switches mode.

Post-commit complete reconciliation is NOT solved by opening a replacement edit. The original may disappear after commit: its 404 blocks and preserves acknowledged, without claiming tester delivery. Public release summaries return at most 20 releases per known track and cannot prove a complete inventory or absence of other edits. The positive end-to-end case supplies a clearly fictional independent complete source; real complete-state and review/edit-coordination providers remain pending. An already-authorized verification edit would itself need reviewed coordination and durable creation handling before adoption; none is created here.

Tests: actual main allocate/validate/publish with unchanged flags and actual validation functions over fictional tool outputs; Python->Node protocol over explicit prefix-replayed deterministic SQL/store fixtures.
