# Restricted promotional caller — code only, no activation

This extends the existing policy validator and production composition, not another ingress/worker/transport. Existing neutral and operational policies and their exhausted counters remain unchanged. No environment value, credential, grant, tariff/budget metadata, migration, real request or plan is changed. New mode `promotional-beta-v1` is usable only by an explicit future policy and pre-existing approved funding/evidence; current production configuration does not select it.

The mode pins one canonical owner digest, sender and recipient, finite approval period (up to31days), reply count, immutable grant amount and the single global program `crewcheck-concierge-shared-budget-v1`. Its monthly USD app budget is exactly20000000microUSD (sharedUS$20, not20perchannel). `maxCostUsd` must exactly match the integer grant amount; decimal conversion is exact. No alternate program ID, reset/refill or approval-ID generation is supported. These schema bounds do not authorize real amounts, periods or recipients. Proposed20replies/7days/US$0.50 is not encoded as a real grant or default.

Raw HMAC, ingress/listener binding, canonical phone proof/consent, account/profile locks, AEAD jobs, request IDs, retry/seen semantics and lifecycle remain existing code. Six-digit challenges are rejected by this mode; it cannot create a link or send link confirmations. Current canonical owner is checked both by store and credit resolver. Admission commits credit+quantity with preparing before engine. A pre-engine scope check blocks late expiry. Immediately before transport, optional store `checkSend` re-reads approval/link/funded-period/tariff evidence and the committed reservation/global reconciliation: revoked approval, expired evidence, increased price beyond reservation or budget overflow blocks send and retains the reservation. Legacy admissions without that capability retain their existing path.

Only bounded known read-only inputs reach the configured canonical engine inside `withConciergeConversationWritesOnly`: complete menu, stable menu numbers, saved schedule/history commands and existing operational classifier. Unknown/mutating/injection/external-lookup requests return a fixed beta limitation message; they do not call tools.12–14 hand off to the app rather than triggering external nearby lookups. Other numbered handoffs reuse the menu producer. A finite credited response can be consumed by a clarification/unsupported-input reply; this must be disclosed in activation terms. No AI, voice, outbound initiation or automatic reservation action is enabled.

The SQL resolver requires approved authority and a granted receipt matching the exact grant manifest and period, current link/revision, target-bound tariff source/hash and genuine verifiedAt/validUntil. It never refreshes evidence itself. Both tariff and global reconciliation currently have15-minute freshness limits. Longer continuous beta therefore remains blocked without an independently reviewed genuine refresh process or a verified bounded cost-ceiling policy. Do not manufacture fresh dates from an old screenshot/quote. Tariff/servicewindow/fees/other consumers and fixed rental must fit the shared budget; this is not a provider invoice hard stop.

Before actual use: independent reviews/exact CI of the stack; reviewed authorized provisioning of one fixed promotional grant and genuine tariff/global obligations; approved owner/audience, amount, count, dates and conservative fees; runtime preflight on current code; specific paid activation. No Asaas payment reconciliation is needed for a truthful subsidized promotion; no entitlement is granted by HTTP200/email/profile hints. This patch does not carry out any activation step.
