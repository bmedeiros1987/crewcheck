The explicit grant writer requires a pre-existing approved authorization record whose manifest binds approval ID, program, canonical owner digest, amount, period and global cap. It verifies a unique exact public account ID; it does not search email hints or phone for ownership. Missing authority/global reconciliation denies. Concurrent/repeated grants produce one receipt and one funded account; an existing balance is never overwritten or topped up. Same approval with altered amount/period denies. The global promotional allocation is cumulative and conservative, never automatically released: allocation plus known spent plus reservations must fit the shared cap. This can under-allocate after usage because accounting overlaps; it cannot be represented as precise invoice settlement. Later settlement/reallocation requires separately reviewed evidence.

Funded accounts carry validFrom/expiresAt. Reservation rechecks those dates after asynchronous SQL, alongside quote/session/reconciliation freshness, and throws to roll back if authority expires after writes. Existing generic account rows without those optional period fields retain the candidate's prior behavior; the promotional SQL resolver requires the approved grant ID and finite dates.
