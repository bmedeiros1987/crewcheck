# CrewCierge company transport (reference-only draft)

Adds “Ônibus e vans da empresa” to the existing app conversation shortcuts, Telegram keyboard/help and `/transporte_empresa` command. Natural corporate-transport questions are handled before the shared planner/nearby resolver. Public transport, financial and unrelated queries stay on their existing paths.

The reply requests explicit origin, destination, service date, and boarding/alighting points or operator when ambiguous. It never derives a trip from GPS or roster base. The app omits cached location from corporate queries; the shared app endpoint also refuses to normalize or persist supplied location for this intent. No new endpoint, notification, paid-message activation, route lookup or persistent conversation cache is added.

The runtime has no installed catalogue reader and displays a clear “not enabled” state. A future **server-owned** `readAuthorizedCatalogue(owner)` must return an envelope with matching `ownerEmail`, nonempty `companyId`, `accessScope: 'private-company-transport'`, `authorized: true`, `eligible: true` and scoped references. Every entry must repeat the same owner/company/scope, confirm eligibility and declare `vehicleType: 'bus' | 'van'`. The record's eligibility must also be confirmed. Profile fields or request-body company claims do not grant catalogue access. Visitors, unauthenticated/access-key-only app callers, groups, unlinked Telegram and WhatsApp are denied private references. No provider or public/private timetable is supplied by this patch.

The adapter shows source, direction, points, service date, timezone, planned boarding times and unknown/known validity. Calendar exclusions, outside-validity dates, missing/ambiguous references, source failures and denied access remain distinct. A bus source never confirms vans. Timetable values never establish live operation, arrival, duration or presentation viability. Unknown transport operation stays unknown.

The reference source was identified by the user as a recent LATAM company website document collected on 2026-10-08; an exact publication date is not available or required for attribution. This is user-confirmed origin, not an independently fetched page. Corporate/public access scope, user eligibility, reservations and exceptions still need clarification before enabling any real data. The original source remains private in Library; this repository and CI contain fictional fixtures only.

This slice is based on main independently of unmerged PR935. It reuses the same pure `companyTransport` contract (including null-query normalization), without importing that PR's departure UI or merging its branch. The existing notification safety finalizer stays last. PR933/934, global menu CSS and financial engines are untouched. Any future composition must retain both preparation adapters.

Tests execute the actual prepared wrapper, app request helper and endpoint. GPS getters, snapshot writes, generic planner calls and network are forbidden in corporate cases. Synthetic negative fixtures cover owner/company mismatches, visitors/groups, eligibility, duplicate routes, reverse directions, calendars, source failure, unsupported vans and no arrival inference. Existing stay-menu and Wellhub tests retain all prior assertions with the new wrapper dependency supplied explicitly.
