# Fixed financial concealment

Reuse `useFinancialPrivacy`, `FinancialPrivacyToggle`, `hiddenValue` and `concealFinancialText`; there is one shared preference, not a new controller per screen. `hiddenValue` is the fixed string `R$ •••` regardless of value magnitude/sign/original currency. Data, calculations and exports are untouched. Dates, field names and rubric labels remain available; monetary values inside text use the same mask. Inputs keep their original state, show no value while hidden, and are disabled where editing an invisible amount would be misleading.

The device stores only `hidden`/`shown` under `crewcheck:financial-privacy:v2:<encoded-owner>`. First client render reads synchronously; absent/unresolved owner and server rendering are concealed. A new account with readable storage and no preference starts visible, preserving the existing default. Storage failure starts concealed; an explicit toggle still works in memory, including write-only failure against an older stored preference. Matching storage events reconcile other tabs. No money, tokens, document text or source data are persisted by this preference.

Changes affect the existing shared hook, calculator, tariff confirmation input and private payroll preview. The Home owner can apply `docs/reviews/financial-privacy-home-integration.patch` to replace two remaining literal placeholders with the exported fixed mask. Home and actRules were not edited. Existing Alterações handoff uses `privacy.amount`/`privacy.text` and inherits this preference after integration. Any future vacation view must do the same, including accessible labels/tooltips. Charts must continue omitting proportional bars while concealed.

The user's navigation suggestion (one Financeiro entry, compact Diárias/Salário/Alterações selector, Férias inside Salário, one top eye) remains a coordinated visual integration item; no broad navigation refactor is included here. All existing toggles share the same state.

Tests use fictitious accounts/amounts only: preference read/write failures and account isolation; actual compiled hook/eye in Chromium at390px; first-render/SSR concealment; constant mask; dates, Swiss grouping, high-precision tariffs and foreign currencies; keyboard; aria/title; reload; hidden tariff input. The existing whole-app privacy regression was adapted to permit only the display-preference write and to expect its persistence on reload.
