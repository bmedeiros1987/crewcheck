# CrewLife v2 Wear receiver

Separate from merged PR1083; base d5afdffa. Implements the parent's agreed phone/Wear contract in crewlife-v2-contract.json. Capability is app protocol discovery only, not permission/consent or evidence of cleanup. No phone/Companion/shared-health edits, SDK, permissions, activation, source queries, signing, versions, device or store actions.

Wear accepts health values only on /crewcheck/watch/crewlife/v2 after directed reset. The reset's source node and opaque stream bind data. Only four allowlisted source metrics exist; zero is a value. The parser requires strict JSON safe integers, original envelope times and per-metric deadlines. Rendering and load never renew time. Unknown/malformed metrics become unavailable; unknown or recursive fields reject the envelope and clear values while preserving the replay fence. Scope excludes narrative, labels, heart rate and HRV.

One SharedPreferences commit clears old/current health ciphertext and persists the node/stream/revision fence before returning reset_ack/revoke_ack. AES-GCM health payload remains separate from operational and routine stores. Migration removes v1 health ciphertext only; later v1 values cannot restore it. Data always replaces the full snapshot. Persisted high water and fingerprints reject lower revisions, conflicting duplicates and replay after malformed replacement. Retired stream nonces are never pruned; at256 retired streams a new reset fails closed. Regrant after revoke needs a new stream. Revoked tombstone before directed revoke still permits a same-revision cleanup ACK; ACK types remain distinct.

Activity observes health preferences, reloads on resume and schedules local redraw at the earliest metric deadline. No health values are displayed in Activity AOD. Complications re-evaluate each metric and carry host validity ending before the earliest rendered metric expiry, including the zero-valued ring. This is not physical OLED/pairing proof.

Compatibility: old phone/new Wear is unavailable; new phone/old or offline Wear is unconfirmed and must be blocked by the phone. New/new requires reset ACK per intended node, consent and sender generation checks. This Wear patch cannot clear an old/offline watch, prove consent, inspect Samsung data or make an old phone obey v2. Phone capability discovery, owner/generation journal, pending cleanup/retries and post-async fences remain PR1085 owner responsibilities and integration gates. No v2 snapshot application ACK is emitted (optional in contract); reset/revoke ACK prove durable local cleanup, not rendering.

Evidence: 38 actual pure JVM tests initially passed locally with synthetic data. Robolectric lifecycle tests cover real DataLayer handler, AES/prefs/cache, persisted ACK ordering, migration, replay, listener, pause/resume and partial expiry. Only Keystore key and outbound MessageClient delivery are shadowed. CI/lint/build and independent review must pass on the final SHA; physical/vendor SDK validation remains pending. Shared JSON vectors are an interoperability input, not proof the phone implementation passes them.

BLOCKER (independent review): after receiver journal loss, a delayed reset for an old stream absent from retiredStreams can replace a current stream; old still-valid data then passes. Reproduced on actual compiled CrewLifeFence: resetB1 → unknown-old resetA1 → old snapshotA2 = accepted. A conforming sender without state loss reduces this scenario but does not cover journal loss expressly in the contract. HOLD integration/release pending joint protocol agreement for receiver-issued challenge or durable ordering across streams. No invented freshness or silent workaround.
