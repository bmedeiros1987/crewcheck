# Shared Concierge credit candidate — OFF

This carries forward the existing unwired candidate from branch `codex/whatsapp-quota-design-20261024` (0d26f906), rather than implementing another ledger. `CONCIERGE_SHARED_CREDIT_SHIPPING=false`; no production imports, bootstrap, route, pool, env, grants, paid entitlement, scheduler, transport or migrations are added. Existing consumed pilots remain separate and untouched. This is not continuous WhatsApp activation or voice activation.

Reservations use the existing state-table interface in the dispatch transaction. A trusted host must hold canonical link/profile locks and provide current consent, exact account identity, binding revision, sender/recipient and a fresh verified quote. The candidate now also requires the canonical account digest to equal the server-stamped job account. A client phone or arbitrary resolver assertion is not independent proof. The SQL test resolver is a fixture, not a deployed authority.

Account credit and one global monthly USD budget are locked in stable order and reserved before engine/provider effects. Duplicate event requests retain their reservation across processes and MySQL restart; changing channel does not recreate balance. Missing grants/budget, stale reconciliation, incompatible quotes or insufficient funds deny. Unknown/failed outcomes never automatically refund or retry. A lost acknowledgement is tested by throwing after a real COMMIT; it is not a simulation of a severed network connection. Transaction rollback tests cover three ledger writes and a downstream preparing marker. The separate-process replay and actual server stop/start are distinct checks.

Only task-owned temporary MySQL8.4 Unix sockets with networking disabled are accepted. Tests verify ownership marker, exact HEAD, socket parent, server datadir, version and skip_networking before any fixture DDL. All schema/data are synthetic. The runner removes only its owned container/directory; local QA artifacts can be retained. No real database/credentials/provider is contacted. No real schema change is proposed.

Remaining blockers before integration: trusted production resolver and its entitlement/revocation contract; idempotent reviewed grants and settlement/refunds with authoritative cost receipts; global budget reconciliation including fixed rent, voice, WhatsApp, taxes/fees/other consumers; counter period/retention policy; actual dispatch lock ordering and lifecycle integration tests; independently reviewed finite admission and specific activation approval. Asaas HTTP200 or email/externalReference/profile hints cannot grant credit. An eligible payment requires exact reconciled canonical account/subscription and financed period. The test's seeded grants are not that implementation.

US$20/month is the shared app-controlled WhatsApp+voice budget, not a provider hard billing cap. Quote parameters are fixtures, not live tariffs. Voice quantum/destination/duration must be verified before any voice activation. No message/voice conversion1:1, new grant on channel preference, recurring billing or real customer balance is introduced.
