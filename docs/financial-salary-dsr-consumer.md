# Local salary DSR consumer

This consumer delegates exclusively to composeSalaryWithDsr and confirmedPayrollDsrContext. No shared financial model, tariff, transport, writer or server admission changes.

`salaryDsrReceipt` assigns an ephemeral calculation revision to an owner/month/input signature. Signature includes the actual engine config/results, roster fingerprint, confirmed rate metadata, monthly settings/revision and the real payroll context. The receipt is memory-only, invalidated by the captured auth continuity fence. It is neither a persistent payroll revision nor server authentication. Source ids contain no token. It must never authorize Concierge sync.

Each full component is amountMinor or null; observations remain separately under observedParts/observedSubtotalMinor. Explicit observed zero and missing observation differ. Unknown KM/time blocks production but does not erase a chief sector with existing eligibility evidence. Legacy global instructor default is not owner-bound eligibility and does not prove observed zero. Missing inventory leaves variable full components null. No DSR partial is calculated outside the shared model. Reported DSR remains separate, scoped to its exact operational/payroll months. Gross and net remain unavailable while full composition is incomplete. Net also requires the existing monthly deduction evidence; no old net survives a changed gross.

Future inventory producer contract (not implemented): owner, operational competence, original publication/source identity and revision, category-specific exhaustive event inventory for every covered day, explicit known empty categories, and invalidation when source/classification/session changes. Coverage must establish both dates and all occurrences/classification; payrollOperationalCoverage's date list, rosterFingerprint and current publication completeDates empty are insufficient. No user/default boolean may mint this evidence. Until that producer exists, observed known work is displayed as a subtotal rather than erased or called complete.

Tests are synthetic/offline only. Confirmed source fixture comes from the real parser/archive producer. No printed evidence is borrowed as provenance for estimated work.

Monetary boundary: only final estimated totals per component/observation are formatted to two decimals using the same Intl policy as existing salary moneyBRL, then converted strictly by decimalToMinor. This is projection precision, not an ACT rounding rule or a rewrite of a printed amount. Tariffs retain all original decimals until their existing engine multiplication. Components are finalized individually before summing integer cents (0.005 + 0.005 across two components becomes 1 + 1 cents). Nonfinite/negative/overflow amounts remain unknown. Shared DSR arithmetic remains unchanged.

Receipt continuity is scoped by owner, operational month and calculation purpose. Forecast replacement invalidates only the preceding receipt for that slot; comparison before/after and other months have separate slots. FinancialHistoryExplorer already omits current when a loaded month exists and rejects conflicted month inventory. No historical archive/paid record is invalidated or edited. The private input signature also records optional manual inputs actually consulted, so equal-value manual-to-learned source changes receive a new ephemeral revision. These are continuity checks, never authentication or transport authority.

Compare preserves operational OP/PS/route/time changes. Its existing integral variable difference and planned-guarantee claims additionally require both category inventories complete; a partial observed amount is not a guaranteed variable total. No comparison engine is duplicated.

## Recovery and summary consistency

The payment adapter now requires the same current, owner/competence-scoped complete canonical composition AND category inventory before certifying a total. It consumes those canonical component amounts and DSR once; scalar rows and a full civil calendar remain observed subtotals. A confirmed zero fixed addition is still known, and an observed zero activity remains an observation. A category missing from a roster is not an explicit category zero. Credit-cycle composition preserves its independently reviewed operational/fixed months.

The inventory producer remains blocked by a specific source contract gap: existing roster/parser outputs do not assert that every occurrence for each of production/reserve/standby/chief/instructor is classified for every covered civil day, nor explicitly certify empty categories, with original source identity/revision. The reconciled payroll DSR metadata proves the reported month/basis, not an exhaustive inventory of a different forecast publication. This patch does not mint that proof, add a confirmation checkbox, carry paid observations into a future month, or set `inventoryComplete:true`. A future producer needs a supported source-format assertion and versioned category mapping before it can supply that proof. Complete adapter fixtures assume this proof explicitly and do not certify an implemented parser producer.

History failures are retained as failed attempts until the user explicitly retries. Request identity and the existing session/source epoch fence prevent an old result from settling or clearing a replacement request. Inventory-read recovery refreshes the read-only inventory; source-read recovery retries failed entries only. No automatic retry loop or server write is introduced. The controls identify ACT applicability separately from source/tariff failures, and the allowance hero distinguishes the work interval from estimated credit date.

Review follow-up: when the real consumer is present, payment subtotals now read its `observedParts`, not the legacy row total (which may include an instructor flag without owner-bound eligibility). Per-flight source details remain in the existing statement. Cross-competence cycles require the complete canonical operational variables/DSR and independently proven fixed components for the payroll month; they do not require that payroll month’s still-open variable inventory. Account/source mismatches retain unknown values. The UI does not promise that an observed subtotal exists when all amounts are unknown.

Remote roster inventory failures retain the existing local fallback. An opt-in `onUnavailable` callback reports the fallback after the real session fence, without error payloads or additional requests; financial coverage remains unconfirmed and the existing screen offers an explicit retry. Other consumers keep their fallback behavior. Fixed components in a different payroll month require BRL, original source id/positive revision, matching owner/competence, full applicability interval, known component amount and no contradictory observation. Unknown operational categories in that fixed month are not required.
