# Financial hierarchy proposal — preview gate

This branch is a proposal for user feedback. Do not merge or deploy the visual redesign until Bruno has seen the preview and provided feedback. PR #1053 (Eye/EyeOff) is already live separately at merge 2286c88; this proposal builds on it. PR #1018 is not integrated. No taxi/import confirmation handler, export builder, compensation tariff, or operational engine is changed here.

The existing allowance and salary pages keep their period consultation, monthly composition, source audit, statement reconciliation and comparisons. A CrewCheck hero and three shortcuts precede those secondary sections. The hero has its own eligible-cycle composition and does not borrow the selected period/month total. Shortcuts reveal the existing statement review or cycle composition and transfer keyboard focus. Missing schedules have a direct route to the existing import view. Existing comparison rows are rendered as compact labeled bar cards; unavailable periods remain explicit and disabled.

Allowance eligibility reuses the observed Wednesday–Tuesday reference, selecting the previous closed cycle when its observed payment reference has not passed. The reference is not documentary proof of a company payday: the hero says “Data a confirmar”. Only rows in that cycle are totaled in original currencies; monthly coverage, each published day, unknown classifications, invalid calendar dates, empty composition and invalid amounts can block the total. Missing information is not treated as zero. Changing the consultation filter does not replace the hero's cycle.

Payroll requires the account's reviewed company cycle. It selects the earliest expected credit month that has not passed (month only, never an inferred day). Fixed amounts come from the fixed-month snapshot; variable flight/activity components come from the operational-month snapshot. Flight totals already contain chief/instructor supplements and those amounts are not added twice. The displayed amount is explicitly a gross estimate before deductions, not net credit, received money or available balance. Incomplete composition stays unavailable and its sources/competences can be inspected. These are projections of existing engine components, not a replacement salary engine.

Synthetic UI coverage includes complete/partial/empty allowance cycles at 390px/1440px, cross-month amount versus monthly totals, independence from consultation filters, reviewed payroll with different fixed/operational months, keyboard shortcuts, Eye/EyeOff on the new complete amount and DOM/accessibility concealment. The standard privacy regression still covers navigation, periods, account switching, reload and real PDF.js review paths. Fixtures register the active month as the latest saved publication so background startup restoration cannot substitute an older fixture. TypeScript, production build and existing allowance/salary caller regressions are also run.

Preview evidence lives under artifacts/financial-payment-preview in CI; the executor's local originals are /tmp/crewcheck-payment-preview. Mobile/desktop, payroll, incomplete states and comparison captures are inspected visually. Library delivery is blocked in this executor: the current helper refresh failed with “skill package is not available” after cloud skills were removed. Earlier independent-stage Library uploads also failed at network discovery. No direct-write workaround or public Library link is fabricated. The preview handoff must not be described as fully delivered to Library until it is actually saved through an available supported connection.

## Operational payroll coverage correction

The initial proposal incorrectly treated a positive day count as complete operational coverage. The corrected projection requires every distinct valid civil day of the operational competence (including published rest days). Empty, one-day, missing-day, duplicate-date and wrong-month input cannot unlock a complete payment. Known fixed pay and valid individual flight portions remain inspectable, while incomplete monthly reserve/standby portions remain unknown. A fully published no-variable month can still have an evidenced zero variable. The component and synthetic regressions share the actual composePayrollPayment projection; browser cases cover complete, one-day and empty operational history with known fixed pay. This correction does not introduce the separately requested settings/defaults, payslip-ledger or contribution expansion. New independent review is required on the corrected HEAD; the visual approval gate remains in effect.
