# Confirmed receipts → held queue → fixed local transport

Base: published PR974 ba3723a426184aadf9f1b1bf8106129f0179c5bd. This separate draft changes only the free-day simulated flow, tests and CI. It does not incorporate PR975 or any additional CrewLocker work.

Voluntary confirmation now reserves one eligible source job in the same owner-locked MySQL transaction as its two minimum receipts. The consent remains preparation-only, never real-delivery consent. Only a matching account generation, valid period/identity/literal clock/UTC offset and matching sequence boundary in both versions can produce a delay. The comparison is recomputed from receipts; cached delay/value/client authority cannot authorize a job. Unknown crew role/ACT leaves compensation null without blocking a qualified declared-source notification. Official authorship remains unverified and is not an eligibility requirement for this simulated alert.

Existing Telegram destination is read only from the server's link-email and link-chat records. Both must agree on account email, numeric chat ID, timestamp/code/username fingerprint; linking must follow account creation and not be future-dated. Missing/old/inconsistent links are pending, never guessed. The authenticated owner sees its existing username with a masked chat suffix; collective chats are explicitly labelled collective rather than inferred from a sender username. No linking flow, new permission, token creation or real test message is invoked. Configuration presence is reported as a boolean, never credentials; no provider configuration is needed for a fixed no-network simulation.

The reserved key is free-day:source:SHA256(accountID,sequenceDate,beforeVersion,afterVersion). Existing terminal reservations are not reactivated. The shared dispatcher still unconditionally cancels every free-day job if forged into processing, before reading a destination or invoking a provider. New rows stay held with chat_id/username/phone NULL and a generic qualified notice; no document, name, raw text, file, schedule details or amount is sent. A separate owner/account metadata key records source versions, minimum comparison information, preparation-consent revision/expiry and the link fingerprint. It contains no real chat ID or username.

GET/POST /api/notifications/free-day-source-queue allow only held preparation and simulation. The fixed local transport has no caller callback, recipient, URL or provider injection and no fetch/timer/real-provider import. It produces simulatedAccepted:true, but accepted:false and delivered:false; a durable audit is written once while account/source/link locks are still held. The row remains held. There is no started worker, recurring task or real activation path. Changing environment flags, configuration presence or request fields cannot turn SOURCE_QUEUE_DISPATCH_ALLOWED=false into an authorization.

TTL is inherited from the 30-day receipt/preparation consent. Expiration commits receipt removal, cancellation of held/pending/processing source jobs and metadata deletion even if the first access is a stale POST. Revocation and replacing the reviewed pair cancel old reservations in the same transaction. Link/context changes also commit cancellation before reporting a conflict. Account deletion covers the metadata prefix and existing queue deletion. Retention cleanup runs on authenticated access/revoke, not a new background daemon. Only cancelled hashed job keys/generic queue text remain as dedupe tombstones; source/link/simulation metadata is removed.

The UI displays only an existing destination validated by the server, offers refresh and local simulation, and disables the specific real-consent control while real delivery is globally unavailable for this flow. It never grants real consent or creates a destination. A new selected PDF blocks preparing a different saved review; extraction confirmations remain tied to exact receipts/date. Account changes/unmounts invalidate late destination responses. Ordinary confirmation with an already-valid link prepares held automatically, reducing an unnecessary second click. If a link becomes available later, the explicit producer can prepare from the saved receipts without re-uploading.

Validation uses only synthetic identities/PDFs, a fixed transport and a disposable --network none MySQL UNIX socket. Physical PDF → parser → confirmed receipts → verified existing destination → browser context closed → server producer/local transport → reopen → revoke is exercised. The same audit survives reading from an independent SQL pool. Tests cover 8-way duplicates, source/job atomic rollback, stale revisions, profile recreation, both sequence boundaries, literal/fuso pending data, TTL/stale POST/revocation, destination rotation and forged processing. Raw/prepared tests, original PR972/974 regressions, TypeScript/build and financial/browser gates are required.

Actual remaining activation steps after this simulation is reviewed: the user confirms the existing displayed destination and grants specific real-send consent; if destination/configuration is absent, the user separately authorizes that setup. Then a separately reviewed/authorized release implements/enables that consent and dispatch transition for held jobs with the tested ownership/TTL/revoke guards. No further receipt-to-queue or no-network end-to-end simulation integration is needed. No real-message test, credential or permission change has begun.
