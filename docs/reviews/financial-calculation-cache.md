# Device-local financial calculation cache candidate

Base f5d041ae1c4c7f464f8d8f84e25d60063c9bda45. Work is the only implementation owner. This candidate is separate from the registered financial ledger and does not enable it, apply DDL, capture reviewed forecasts, migrate accounts or synchronize devices.

The existing financeSnapshot entry point reuses disposable calculated data by account, nominal competence and calculation scope. Dependency identity includes the complete current roster, relevant financial settings/rates/ACT applicability/profile rank/adjustments, registered profile, operational day in BRT and build identity. An exact source digest mismatch runs the original engines. Unknown build identity disables durable reuse. A day change invalidates weekly projections; there is no claim that clock-dependent projections remain current indefinitely.

Only calculation data are persisted in this browser's localStorage. The stable canonical account ID is retained for account binding (not a mutable email address). No token, profile name, raw source text or PDF is stored in cache metadata: inputs enter a SHA-256 identity. Calculated financial rows remain private device-local data. Entries are bounded to 128k characters and an aggregate 1MB byte estimate; quota/blocked storage falls back to calculation and memory reuse without evicting application or historical records. A checksum detects accidental corruption, not authenticity. This is an estimate cache, never proof of payment, employment or official payroll.

DSR receipts and isCurrent functions are deliberately excluded. Current-session DSR evidence is reconstructed with the existing salaryDsrReceipt/consumeSalaryDsr and current reviewed context; gross/net are recomposed with the existing functions. Component completeness and unknown/zero distinction are retained. Reauthentication may reuse same-owner core data but cannot reuse an old session fence. Source changes invalidate earlier DSR receipts. Cache writes replace only their own disposable slot; a stale-tab entry cannot match a newer dependency identity. Context changes during work fail closed. The first uncached calculation remains synchronous. A source change during reconstruction revokes the affected ephemeral DSR receipt and interrupts the result. The existing error boundary and Home estimate show a short pending state with retry, preserving the session and hiding the previous amount; unexpected errors retain the original protection. This is not asynchronous calculation or physical-device latency validation.
