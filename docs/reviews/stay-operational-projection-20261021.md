# Saved stay operational projection

The existing account-scoped stay-editor v2 record is the local source. Hotel and room require the original occurrence signature; hotel APZ additionally requires its explicit date, IANA zone and manual confirmation. The shared existing stay calculator supplies the proposal, including individual lead/exact choices and breakfast-dependent Auto. No flight departure is substituted for an unresolved active stay.

Home's general wakeup screen selects only one unambiguous current stay. It retains the original flight event ID and event instant for scheduled-job conflict detection. Saving or editing a stay only updates the local proposal. It never cancels, edits, recreates, dispatches or automatically schedules any server job. An existing pending job remains visible with its original scheduled instant, and duplicate admission stays blocked. No real job was queried or changed by development tests.

Operational hotel editing now enters the same canonical editor instead of writing the separate platform hotel cache. Legacy platform APZ is never promoted to confirmed hotel APZ. Date-only fallback matching is removed. Standalone hotel records without a roster occurrence remain non-operational.

The existing Watch producer may project the validated hotel name into its existing hotel field and retain its existing confirmed APZ field. Room remains local-only and is excluded from Watch payloads. This does not enable the native host, change replay authority, distribute an APK, or prove delivery to a physical Watch.
