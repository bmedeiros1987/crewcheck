# Voluntary two-version review — preparation only

Base: PR972 merged main fecef8178cefe8eb4f6e7d04085e4bdd2fc5d878. No changes to its held job flow, dispatcher, consent scope, provider configuration or dispatch flag.

A signed-in owner voluntarily selects two PDFs in the existing app. Production PDF.js/parser reads them locally. A separate API receives exactly a SHA256 document declaration, SHA256 crewID/base identity digest, year/month, rest dates and literal clocks/UTC offsets. It receives no files, names, raw text, filenames, flights, rank, salary, chat ID, recipient or ACT assertions. The server matches identity against the authenticated owner's single active stored roster and binds the state to the current profile public ID, preventing account recreation from inheriting an earlier state. Existing roster data is already imported; no new account/document access is introduced.

The document hash establishes a declared content fingerprint, not company authorship. The stages are explicitly distinct: selected source is **declared**, explicit user review is **user-confirmed declaration**, and **official origin verified remains false**. The UI never offers an official-verification checkbox and the server rejects an officialVerified field. A user confirmation does not prove the PDF was published by LATAM. Literal evidence is preserved only if code/date/clock/source/timezone provenance agree; otherwise the receipt retains the rest date with null clock/offset and an explicit pending result. Invalid dates are rejected. Both versions must have the same sequence boundary. Identical documents/versions are pending, including without a literal start. Time calculation uses the source UTC offsets, independent of device timezone. No monetary amount is asserted without verified role/ACT; possibleAmount is always null in this preparatory flow.

Two immutable minimal receipts are stored together under a separate owner/account state key. Monthly sync may overwrite its active roster; it cannot alter an already saved pair. Saving another review explicitly replaces the pair; this is not an unbounded version archive. Consent covers only preparation of free-day alerts with these minimum data, is separate from PR972 consent, expires after 30 days, and is protected by a profile lock and revision compare-and-swap. Replaying the same owner/sequence/versions does not create another review or extend expiry. Revocation physically replaces state with a minimal revision tombstone, removing both receipts. On authenticated access after expiry, receipts are physically removed; without a subsequent access physical deletion is deferred. No cleanup daemon has been introduced. Account deletion includes this state prefix. This exact retention limitation appears in the UI.

GET/POST /api/notifications/free-day-sources are explicit requests only. They create no queue job, read no Telegram link, start no timer, and invoke no provider. dispatchAllowed, delivered, officialVerified and linkVerified remain false. UI inputs and late asynchronous responses are cleared/ignored across account changes. The API accepts no client recipient/value/source-authority fields. Server authentication is the existing JWT mechanism; no new credentials or permissions.

Validation: synthetic physical PDF through the production parser, consent UI and actual local HTTP handler in UTC/Sao Paulo/Tokyo; 404-minute fixture; minimal POST audit; two required checkboxes; revoke removal and account switch; pending dates/literals/versions/sequence shifts; CAS, concurrent writes, rollback, account recreation and monthly overwrite. Disposable MySQL uses only an isolated UNIX socket, --network none, fixture identities and no real destinations/providers. Raw/prepared regressions and web build are required CI gates.

Remaining delivery blockers: a trustworthy official-source verifier; verified crew role/ACT for compensation; verified current Telegram ownership/link/configuration; integration with PR972 reservations under aligned explicit consent; independent review and a separately authorized delivery activation. No test message or app-closed alert has been sent. This PR makes source declarations reviewable, not officially authenticated, and completes only a simulated end-to-end path.
