# Restricted test sender contract (preparation only)

No gate, recipient, credential, service or live transport is configured by this patch. Empty test profile preserves the approved baseline. Any nonempty profile must be exactly `restricted`; malformed, incomplete, unreviewed or drifting configuration fails closed. Attestation flags record a review, not proof of isolation, Meta approval, pricing or zero cost.

The restricted profile requires exactly two distinct recipient numbers supplied later in the environment, a configured test Phone Number ID matching the existing sender, and explicit transport/isolation attestations. No real values belong in the patch. Central send policy requires the same recipient/receiver/message ID as a scoped inbound reply, a known timestamp not in the future and strictly younger than 23h, and an approved path. It rechecks configuration/window immediately before fetch. There is no template, paid fallback or retry.

Paths: signed webhook ordinary dispatch carries an immutable minimal reply scope; owner six-digit link acknowledgement is allowed; deterministic menu commands are allowed only through the gated menu; visitor replies retain their canonical binding/Premium/resource/revocation guard; durable PDF confirmation reconstructs scope from its queued envelope and matching profile stamp. Direct/proactive sends, arbitrary menu/AI/place inputs, unconfigured/unsupported legacy handling and jobs inherited from another profile are blocked in restricted mode. Queue import is checked before media retrieval. Existing gates remain OFF, so unsupported paths stop rather than enabling an old-production fallback.

Covered negatives: missing/non-allowlisted/cross-recipient, wrong receiver/message ID, unknown/expired/future window, expiry during awaited work, invalid/unattested/profile drift, missing scope, unsupported legacy/menu and profile-stale PDF job; revoked visitor must never reach send. Synthetic positives cover owner link/menu, scoped visitor and matching PDF confirmation. Native authorization locks are unchanged; up to10s transport duration is still not an atomic DB/Meta transaction. Full native login/DB isolation, real sender/app/WABA binding and actual pricing remain external prerequisites.
